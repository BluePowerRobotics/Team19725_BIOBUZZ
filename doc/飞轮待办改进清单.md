## 一、当前基线（改进的起点）

`PrototypeShooter` 已固化 2026-09-04 整定结果：

| 参数 | 值 | 说明 |
|---|---|---|
| kS | 0.02945 | **静摩擦前馈（占空比）**，稳态模型 `d_ss(ω)=kS+kff·ω` 的截距 |
| kff | 0.00038307 | 稳态前馈 (占空比)/(tick/s)，稳态模型斜率（已扣除 kS 项） |
| kp | 0.00181917 | kp×一个量化台阶(20 tick/s) = 0.036，已达标 |
| ki | 0.00259224 | 积分增益 |
| maxI / iZone | 0.3 / 500 | 积分限幅与生效带 |
| dropThreshold | 100 | 掉速判定阈值 (tick/s) |
| dropRateThreshold | 12000 | 掉速速率阈值 (tick/s²) |
| kBoost | 0.00362834 | ≈2×kp，符合 2~5Kp 规则 |
| boostMax / boostDurationSec | 0.4 / 0.3 | 补偿上限与时长 |
| motorReversed | true | 实机反向接线（非整定量） |

控制律已独立为 `utility/Shooter/FlywheelCalculator.java`，由 `PrototypeShooter` 每帧同步参数。
控制律现为 `duty = kS·sgn(ω*) + kff·ω* + kp·err + ki·∫err + boost`。

**已达到的水平**（第四条带球日志实测）：稳态转速波动 ≈0.5 个量化台阶、稳态误差 0.10%、占空比 sd 0.018；
发射掉速 13/13 次触发补偿，跌幅中位 270 tick/s，恢复中位 0.43 s。

## 二、未实现的改进方案（按优先级）

### P1 — 确定收益、零成本、纯代码

| # | 改进项 | 依据 | 建议做法 |
|---|---|---|---|
| 2 | **发射门控判据** | 恢复后仍过冲 2.5~4%（+50~90 tick/s），立刻发射会偏高 | 自动发射逻辑里要求 `|e| ≤ max(2%·ω*, 2 个台阶)` **连续 10 帧（≈0.1 s）** 才允许发球；随 TeleOp 集成一起做 |
| 3 | **量化台阶自检告警** | kp×一个台阶 ≳0.05 时输出会随反馈跳变而抖振（kff 那次 0.381 的教训） | 在 `FlywheelCalculator` 或遥测里加一行判据：`kp × 台阶 > 0.05` 时遥测报警（台阶可由离线 gcd 或常量化 20 tick/s 给出） |

### P2 — 需要上机复测

| # | 改进项 | 依据 | 建议做法 |
|---|---|---|---|
| 4 | **工作点多点复测，重标 kS / kff** | log3 里 500/750 档只停 0.62/0.57 s、1500 档只停 0.10 s，短于 1 s 稳态窗口，其数据是暂态污染值（曾把 kS 高估到 0.13） | 每档**停 ≥2 s**，档位覆盖实际使用转速（1700/2050/2250 附近各 3~4 点），再做一次 `d_ss(ω)=kS+kff·ω` 线性回归 |
| 5 | **阶段①「无控制器极限扫描」补做** | 原设计的三阶段①（开环逐级功率 → 极限转速 + 对应电压）没有实机执行过；现有极限认知（满占空比 ≈2400 tick/s）是从带球日志反推的 | 用 `ShooterTuningTester` 的 MODE_KS/MODE_KV，或临时开环逐级加功率，记录「功率-转速-电压」三点表，明确静摩擦起转点与饱和区 |
| 6 | **kD 微调压超调** | 加速超调 2.7~3.0%（高速段）、低速段百分比是量化假象 | 可选：加很小 kD（作用在测量值，`kD ≈ kp×0.02~0.05 = 3e-5~9e-5`）；当时结论是**先不动参数**，因为超调主因是机械惯性 τm≈0.2 s，且发射间隔中位 8.18 s 远大于恢复时间 |

### P3 — 需要硬件 / 战术决策（不是参数问题）

| # | 改进项 | 依据 | 说明 |
|---|---|---|---|
| 7 | **提高母线电压 / 供电能力** | 恢复期占空比 13/13 顶到 1.000，而此时电流只有 2.09 A（峰值 3.35 A，堵转 9.2 A）→ 限制来自反电动势而非电流 | 换更高 C 电池、缩短线损、避免低电量测试；这是**唯一能直接提高满占空比加速度**的手段 |
| 8 | **降低工作转速** | 满占空比加速度：1750 档 1146 tick/s² → 1950 档 816 → 2050 档 694 → 2250 档 497，从 1750 到 2250 掉 2.3 倍 | 同跌幅下，2050 档恢复 0.39 s vs 2250 档 0.58 s（**快 1.47×**）；若弹道允许，降 200 tick/s 就能显著加快恢复 |
| 9 | **传动比 / 电机 / 飞轮惯量** | 同上：恢复时间 ≈ 跌幅 ÷ 满占空比加速度，跌幅由球动量决定，控制器无法改善 | 硬件级改动，需权衡弹道一致性 |

### P4 — 可选（信息增强）

## 三、下次上机的复测清单（建议顺序）

1. 用 `FlywheelRun` 确认 Start→1700 起步、方向键 ±100、X 停 / A 重启，并观察统一 5 行遥测（目标/当前/power/电流/电压）。
2. 每档停 ≥2 s 做多点稳态记录（覆盖 1700 / 2050 / 2250）→ 复标 kS 与 kff（对应 P2-4）。
3. 开环逐级功率扫描，补齐「功率-转速-电压」表（对应 P2-5）。
4. 投球复发 10 次以上，确认：boost 触发率、跌幅、恢复时间、恢复后过冲；与本次基线（0.43 s / +50~90 tick/s）对比。
5. 确认 kS 前馈的效果：看各档稳态**积分项是否回到 0 附近**（此前各档 I 项全为 −0.04~−0.06，即前馈过给 6~7%）。
   注意 kS 只影响稳态与过渡的"底子"，**不会改善发射恢复时间**（恢复期输出已 100% 饱和）。

## 四、已实现（附录，避免重复提出）

- **静摩擦前馈 kS（原 P1-1）**：新增 `kS·sgn(ω*)` 项，并把前馈成对改为 `kS = 0.02945` / `kff = 0.00038307`。
  依据：`tools/tuning/fit_steady_state_model.py` 对 3 次日志的 8 个稳态工作点做 `d_ss(ω) = kS + kff·ω` 回归
  （R² = 0.9949、RMS 残差 0.98% 占空比；只用尾部 1 s 内 ω sd ≤ 25 tick/s 的点，自动剔除未稳态段）。
  此前各工作点积分项全为负（−0.040 / −0.051 / −0.055 / −0.057，前馈过给 6~7%）；改后积分有了回零的基准。
  `sgn` 已实现为 `targetVel > 0 ? 1 : (targetVel < 0 ? -1 : 0)`，`ω* = 0` 时为 0。
- 掉速检测「武装」规则：进入稳态前不触发补偿、目标一改即解除武装（修「启动加速段被误判掉速 → boost 全程挂着 → 到速后过冲」）。
- 三个 Tuner 的整定缺陷修复：`TuningLogger` 表头与注释行、`FeedforwardTuner` 独立测量计时器（修 CSV 时间轴非单调）与饱和标记、`DropDetectionTuner` 量化台阶 + EMA 平滑减速度、`ZieglerNicholsTuner` warmupSec 与改 kp 清缓冲。
- 离线分析链：`tools/tuning/` 下 Python 与 MATLAB 双实现（整定数据 `analyze_tuning.py/.m`、遥测日志 `analyze_dashboard_log.py`、发射事件 `analyze_launch_events.py`、转速图 `plot_speed.m`、数据表导出 `export_clean_table.py`、稳态模型回归 `fit_steady_state_model.py`、自检 `check_plot_data.py`），以及《飞轮转速图分析指南.md》（已移入 `doc/`）。
- 参数固化：kff/kp/ki/kBoost/dropThreshold/dropRateThreshold 已按实机整定值写入 `PrototypeShooter`。
- 控制律独立：`utility/Shooter/FlywheelCalculator.java`（纯计算、可离线复算），`PrototypeShooter` 每帧同步参数。
- 统一遥测：飞轮标准 5 行（目标 / 当前 / power / 电流 / 电压），`telemetryDetailed` 可临时展开分量。
