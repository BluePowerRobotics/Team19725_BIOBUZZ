## 1. 数据链：一次设定速度到飞轮转起来

```
手柄 DPad ─► PrototypeShooter.targetVelocity        (static int, tick/s)
              │
              ▼  每帧 update()
        calculator.calculate(ω*, ω)
              │
              ├── kS · sgn(ω*)        静摩擦前馈（只对抗摩擦，不产生转速）
              ├── kff · ω*            稳态前馈（稳态模型的斜率）
              ├── kp · err            比例
              ├── ki · ∫err·dt        积分（|err| < iZone 才累加，触发补偿时清零）
              └── boost               掉速补偿（仅掉速判定成立时，限幅 [0, boostMax]）
              │
              ▼  sat(·, dutyMin, dutyMax) → duty
        motor.setPower(duty)   ── RUN_WITHOUT_ENCODER：setPower 即占空比
              │
              ▼
        V ≈ V_bus · duty → I = (V − Ke·ω_m)/R → T = Kt·I →（同步带）→ Jeq·dω/dt = n·Kt·I − Beq·ω − T_L
              │
              ▼
        编码器 → DcMotorEx.getVelocity() → 回读 ω，进入下一帧
```

四个容易踩的点：

1. **dt 就是帧时间**（含 `telemetry.update()` 的开销），约 9.5~10 ms；`calculate` **一帧只能调一次**，否则积分与微分会重复累加。
2. **启动段由 P 主导**（前馈不够，误差大）；**稳态由前馈主导**（P、I 只做微调）。所以前馈必须先准，否则积分长期顶在非零值。
3. **掉速必须「先稳后触」**：目标一改就解除武装，误差回到 `dropThreshold` 以内才重新武装。否则从 0 拉起会被误判成掉速。
4. **停转是滑行**（`ZeroPowerBehavior.FLOAT`），不是刹车；`targetVelocity = 0` 时 kS 项因 `sgn(0)=0` 自动消失。

## 3. 采数据前：先量三把尺子

任何「稳态误差」「阈值」「超调」的讨论，先报这三件事，否则结论没有意义：

1. **量化台阶**：本机速度反馈只有 20 tick/s 一档（`gcd` 求出的最小公倍），
   由 `analyze_dashboard_log.py` 自动报出。**稳态误差不可能小于半个台阶（10 tick/s）**；
   更关键的是：**目标转速本身不在 20 的网格上**（1950、2050 都不是），所以任何整数目标的稳态误差天然有 ±10 tick/s 的底噪。
2. **±2% 带 vs 一个台阶**：目标 1000 时 ±2% = ±20 = 正好一个台阶；目标 250 时 ±2% = ±5 = **0.25 个台阶，该判据物理不可达**。
   低速档讨论百分比会得出荒唐结论（4~12% 的"超调"其实只有 1.5~3 个台阶）。
   建议判据写成 `|err| ≤ max(2%·ω*, 2 个台阶)`。
3. **采样率**：约 100 Hz（9.5~10 ms/帧）。低于此的"快速振荡"是采样假象；`dt` 别用日志里的 time 列算（见下条）。

**日志处理铁律**：FTC Dashboard 导出的 CSV 里 **`time` 列的毫秒字段是坏的**（同一秒内会从 ~900 跳回 ~100，每次实验几十处），
按它排序会凭空造出锯齿形暴跌。**必须按文件行序重建均匀时间轴** `dt = 总时长/(n−1)`。
本仓库所有分析脚本都已这样处理，不要自己再算一遍。

## 4. 参数整定顺序（八步）

顺序不能乱：前一步没达标，后一步的判据会被污染。

### 第 1 步 `kS` / `kff` —— 稳态前馈（决定稳态与过渡的底子）

- **方法**：采多个稳态工作点的 (ω, duty)，回归 `d_ss(ω) = kS + kff·ω`。
- **工具**：`python tools/tuning/fit_steady_state_model.py out/clean/*.csv`
  （自动剔除未进入稳态的段：末尾 1 s 内 ω sd > 25 tick/s 的点会打印 `[剔除]`）。
- **当前值（2026-09-04 实测 8 工作点回归）**：`kS = 0.02945`、`kff = 0.00038307`，R² = 0.9949，RMS 残差 0.98% 占空比。
- **判据**：每个工作点的**积分项应收敛到 0 附近**。若各工作点的 I 项系统性同号
  （历史现象：全都为 −0.04~−0.06），说明前馈整体过给，先把这一步重做，而不是去调 kp/ki。
- **注意**：`kS` 按 `kS·sgn(ω*)` 施加，`sgn` 不可省，否则停转指令下飞轮会自己转。

### 第 2 步 `kp` / `ki` —— 反馈增益（决定抖动与响应速度）

- **方法**：阶跃响应辨识（Tune6.1）得到 `Kd = Δω/Δd` 与时间常数 τ，再按零极点对消
  `kp = τ/(Kd·τc)`、`ki = 1/(Kd·τc)`，`τc ≈ T_recover/(3~5)`。
- **粗起点**：`kp ≈ 0.2/Kd`（宁可小，抖动比迟钝难治）。
- **量化台阶自检（必做）**：`kp × 一个台阶(20 tick/s)` 就是"反馈跳一格造成的占空比跳变"。
  - `< 0.02`：好（一个台阶只引起 2% 占空比变化，被机械惯性滤掉）
  - `0.02 ~ 0.05`：可接受
  - `> 0.05`：**必抖**。历史故障值：`kp = 0.019` → `0.019×20 = 0.38`，实测占空比 sd 0.204、极差 0.853、
    占空比在 0.15~1.0 之间横跳而转速只在 ±1 个台阶内抖 —— 这是"用大炮打蚊子"，电流尖峰与发热都白付。
- **当前值**：`kp = 0.00181917`（kp×台阶 = 0.036，达标）、`ki = 0.00259224`。
- **判据**：稳态 duty sd < 0.05（当前实测 0.018~0.020，优秀）；向上阶跃超调 < 5%。
  加速段超调本身**不是故障**：P 项一上来就 >1 被限幅是设计使然，真正的超调来自机械惯性（τm ≈ 0.2 s）与检测滞后。

### 第 3 步 `maxI` / `iZone`

- `maxI`（占空比）限幅积分项并回算积分（抗饱和），当前 0.3；`iZone`（tick/s）限定积分生效区间，当前 500。
- **判据**：稳态 I 项应远小于 maxI。若 I 项经常贴到 ±maxI，说明前馈没做对（回第 1 步）。

### 第 4 步 `dropThreshold`（掉速判定阈值，tick/s）

- **方法**：统计正常工况下的稳态速度波动 σ（约 10 tick/s），取 `Δω_th = kσ·σ`，kσ = 3~5。
- **还要看**：正常发射的掉速深度（本机 250~290 tick/s），阈值必须明显小于它。
- **当前值**：100。历史值 300 太钝（配 8000 的速率阈值时，启动段误触发把 boost 全程挂着 → 到速过冲）；
  20 太灵敏（稳态抖动就触发，log2 里 boost 有 21.1% 时间在误动作）。
- **判据**：**正常发射 100% 触发、稳态 0% 触发**。当前实测 `dropThreshold = 100` 恰好满足（13 次发射全部触发，稳态无误触发）。

### 第 5 步 `dropRateThreshold`（掉速速率阈值，tick/s²）

- **方法**：`k_th = k_rate · max|dω/dt|_{正常工况}`，k_rate = 2~3。
- **注意**：dω/dt 用相邻样本差分会被量化噪声放大（20 tick/s ÷ 10 ms = 2000 tick/s² 的假信号），
  分析脚本用 EMA(α=0.3) 平滑后再取最大值。
- **当前值**：12000。正常抖动约 −2100，发射瞬时可达 −4000 以上。

### 第 6 步 `kBoost`（补偿增益）

- **方法**：`kBoost ≈ (2~5)·kp`；当前 `0.00362834 ≈ 2·kp`。
- **现实**：发射掉速时输出几乎瞬间顶到 `dutyMax`，**所以 kBoost 的大小对恢复时间几乎无影响**（见第 9 节）。
  它的作用主要是让补偿"更快到位"以及应付小扰动。

### 第 7 步 `boostMax` / `boostDurationSec`

- `boostMax`（当前 0.4）与 `boostDurationSec`（当前 0.3 s）限制补偿的幅度与时长。
- **判据**：若 boost 项每次都顶到 `boostMax`（实测 13/13 次），说明限幅在起作用 —— 但**若此时 duty 已经饱和到 1.0，提高 boostMax 不会让输出更大，改名无意义**（历史脚本里的自动提示在这一点上是错的）。

### 第 8 步 复测

改完参数必须重采一轮：稳态 3 个以上工作点 + 至少 10 次发射，然后跑
`analyze_dashboard_log.py`（稳态/饱和/增益反演）与 `analyze_launch_events.py`（发射恢复）。

## 5. 判据速查

| 指标 | 好 | 可接受 | 差 |
|------|----|--------|----|
| 稳态误差 | ≤ 1 个台阶 | 1~2 个台阶 | > 2 个台阶 |
| 转速 sd | ≤ 1 个台阶 | 1~2 个台阶 | > 2 个台阶（持续振荡） |
| 占空比 sd | < 0.05 | 0.05~0.15 | > 0.15（增益过大） |
| 饱和占比（稳态） | 0% | < 5% | > 10% |
| 向上阶跃超调 | < 5% | 5~10% | > 10% |
| 发射恢复时间 | < 0.3 s | 0.3~0.5 s | > 0.5 s |
| kp×一个台阶 | < 0.02 | 0.02~0.05 | > 0.05 |

> 上面每一档都必须在**已知量化台阶与目标值**的前提下使用；低目标时百分比判据不可达。

## 6. 症状 → 真因 → 改什么

| 症状 | 真因 | 处置 |
|------|------|------|
| 稳态转速只在 ±1 台阶内抖，但占空比大范围横跳、电流尖峰大 | P 增益相对量化台阶过大 | 减小 kp（先算 kp×台阶） |
| 各工作点积分项同号且不为 0 | 前馈整体偏大/偏小 | 重做第 1 步 kS/kff 回归 |
| 低速档稳态误差百分比很大 | 量化台阶（±10 tick/s 底噪） | 不是故障；改百分比判据 |
| 启动到速后过冲 | 掉速检测在加速段就触发、boost 常挂 | 武装规则（已有）+ 提高 dropThreshold |
| 稳态莫名触发 boost | dropThreshold 太小 | 按 kσ·σ 重算（当前 100） |
| 发射恢复慢 | 恢复期 duty 已 100% 饱和 → 受满占空比加速度限制 | **加增益无效**；提高母线电压 / 降低工作转速 / 改传动比（见下节） |
| 恢复后过冲 2~4% | boost 退出后 P/I 残留 | 发射门控等稳定再打；或略减 boostDurationSec |
| 目标根本到不了 | 目标超过了满占空比对应的极限转速 | 先做极限扫描；换电机/传动比或降目标 |

## 7. 发射恢复为什么加增益没用（本机实测结论）

带球日志 13 次发射的量化结果：

| 工作点 | 跌幅 | 恢复时间 | 满占空比加速度 |
|--------|------|----------|----------------|
| 1750 | 290 | 0.253 s | ≈ 1146 tick/s² |
| 1950 | 270 | 0.331 s | ≈ 816 |
| 2050 | 270 | 0.389 s | ≈ 694 |
| 2250 | 290 | 0.584 s | ≈ 497 |

- 13/13 次**恢复期占空比顶到 1.000**，13/13 次 boost 触发 —— 控制器已经"全油门"了。
- 2250 档满占空比时电流只有 2.09 A（堵转 9.2 A）：反电动势把可用电流压小了，
  **恢复时间 ≈ 跌幅 ÷ 满占空比加速度**，跌幅由球动量决定，与增益无关。
- 结论：**只能提高满占空比加速度** —— ① 提高母线电压/缩短线损（换新电池）；
  ② 降低工作转速（2050 比 2250 快 1.47×）；③ 改传动比 / 换电机 / 减小飞轮惯量。
