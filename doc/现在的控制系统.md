## 一、简略描述

### 1.1 一句话

**前馈（静摩擦 + 稳态模型，按母线电压归一化）+ 比例（作用在滤波后的速度上）+ 积分（只在稳态窄带内累加，掉速期间冻结）**，输出占空比并饱和到 `[0, 1]`。没有 boost、没有 kD、没有自适应 PID。

### 1.2 控制律

```text
e_raw = ω* − ω
ωf    = EMA(ω, τ(|e_raw|))              // τ 在 30 ms ↔ 8 ms 之间随误差调度
e_f   = ω* − ωf
s     = clamp(V_nom / V_busFilt, 0.85, 1.25)
ff    = s · (kS·sgn(ω*) + kff·ω*)
duty  = sat( ff + kp·e_f + ki·∫e_f dt , 0, 1 )
```

### 1.3 五个机制，各自解决一个问题

| 机制 | 解决什么 | 关键参数 |
|---|---|---|
| 前馈 `kS·sgn + kff·ω*` | 给定目标就把占空比送到位的 70~85%，反馈只修残差 | `kS=0.02945`、`kff=3.8307e-4` |
| 电压归一化 `s` | 同一目标在不同电量下要的占空比不同 → 积分长期负重 | `vBusNominal=12.0`、`tauBus=1.0 s`、`useVoltageNorm`（默认关） |
| 误差调度速度滤波 | 压住 20 tick/s 量化噪声，同时不在冲击段拖后腿 | `tauVMax=0.030`、`tauVMin=0.008` |
| 积分冻结 | 恢复过程不攒积分 → 过冲从 +50~90 降到 +10~20 | `iFreezeTimeoutSec=1.5`、`eBand` |
| 到位判据 `isSettled()` | 发射门控：没稳就不许发，避免把「正在恢复」当成「已到位」 | `settleFrac=0.02`、`settleFrames=10` |

### 1.4 两个飞轮、两套参数

`FlywheelParams.BIG` / `FlywheelParams.SMALL` 是两套**完整**参数（增益 + 滤波 + 电压 + 限幅 + 堵转上限）。
`PrototypeShooter` 默认用 `BIG`；`Controllers/Turret/Shooter` 的 `Params` 内嵌一个 `FlywheelParams`，
`Turret` 构造时给大球传 `Shooter.BIG_PARAMS`、给小球传 `Shooter.SMALL_PARAMS`。
调用方每帧 `params.applyTo(calculator)` 同步一次，Dashboard 改值实时生效。

> 注意：`SMALL` 目前全部是大球值的**占位拷贝**，小球飞轮**从未标定**（历史实测 2026-09-05 18:55：
> 目标 1700、kS=0 时稳态偏 +10.9/+27.3 tick/s）。小球上机前必须按第 6 节流程单独整定，逐项替换。

## 二、详细描述

### 2.1 量纲与符号

| 符号 | 含义 | 单位 |
|---|---|---|
| `ω*` | 目标转速 `targetVel` | tick/s |
| `ω` | 实测转速 `motor.getVelocity()` | tick/s |
| `e_raw` | 原始误差 | tick/s |
| `ωf`、`e_f` | 滤波后转速、滤波后误差 | tick/s |
| `V_bus` | 母线电压（所有 `VoltageSensor` 取最小正值） | V |
| `duty` | 输出占空比 `motor.setPower` | 1 = 满占空比 |
| `kS` | 静摩擦前馈 | 占空比 |
| `kff` | 稳态前馈 | 占空比/(tick/s) |
| `kp`、`ki` | 比例、积分 | 占空比/(tick/s)、占空比/(tick/s·s) |

本类**不持有硬件引用**（`FTC_Format.md`：utility 层不得控制部件、不得依赖 Controllers），
电机、遥测、电压传感器读取全在调用方完成，因此同一份代码可离线回放原始日志。

### 2.2 为什么是「前馈 + PI」而不是「PID」

- **前馈**是主项：1700 tick/s 时 `kff·ω* = 0.651`，加上 `kS = 0.0295` 一共 0.68，
  即 68% 的占空比由模型直接给出。反馈只负责模型误差（实测残差 ≈ RMS 0.98% 占空比，`R²=0.9949`）。
- **kD 不做**：量化台阶 20 tick/s，采样约 8.7~9.0 ms，差分噪声被放大后
  `kD ≈ kp×0.03 = 5.5e-5` 就能造出 0.126 占空比抖动。过冲的根因是执行器饱和 + 积分，
  不是阻尼不足，加 kD 是治错病。
- **积分必须限幅**：`maxI=0.3`，且限幅时**回算** `integral = maxI/ki`，防止「积分看起来没爆、
  实际内部已经绕过一圈」的隐性饱和。

### 2.3 量化台阶决定 kp 上限（本项目最重要的经验判据）

编码器测速的最小分辨是 **20 tick/s**（8 个工作点数据的最大公约数）。kp 把一格测量噪声
放大成 `kp × 20` 的占空比扰动，这就是**量化极限环幅值的下限**：

| `kp×台阶` | 表现 |
|---|---|
| ≤ 0.02 | 好：duty 抖动在 2% 以内，几乎看不出来 |
| ≤ 0.05 | 合格（当前 0.0364） |
| > 0.1 | 差：必然跑出明显极限环 |

历史证据：log2 曾用 `kp=0.019`（`kp×台阶 = 0.381`）→ duty 标准差 0.079、51 ms / 1.50 台阶的
极限环、boost 误触发率 21.1%；改回 0.00182 后 duty 标准差 0.0182、28 ms / 0.50 台阶、误触发 0%。

**结论：kp 的取值不是任何公式能算出来的**——模型式（相角裕度 / 内模）给出的 6.1e-4~9.8e-4
都偏小，最终值是 `0.05 / 20 = 0.0025` 这个量化上限往下取的结果。运行时遥测里的
`kp*step` 行会在超过 0.05 时标 `HIGH`，这是唯一需要现场盯的告警。

### 2.4 误差调度速度滤波（τ 随误差走）

```text
eBand = max(0.02·|ω*|, 2×20)          // 1700→34, 2050→41, 2250→45 tick/s
lo = eLoFrac·eBand, hi = eHiFrac·eBand
blend = clamp((|e_raw| − lo)/(hi − lo), 0, 1)
τ = tauVMax + (tauVMin − tauVMax)·blend
α = dt/(τ + dt);  ωf += α·(ω − ωf)
```

要点：

1. **一阶滤波对斜坡是「幅度打折」，不是「平移延迟」**。发射时转速以 ≈13500 tick/s² 的
   等效速率在 20~25 ms 内跌 270，滤波后看到的是 `y(t)=R(t−τ(1−e^{−t/τ}))`。
   τ=30 ms 时冲击末只看到 **73（真值的 27%）**，连饱和都进不去（`e_desat=102`）；
   τ=8 ms 时看到 171，14 ms 进入饱和。这就是必须做误差调度的定量理由。
2. **调度只能用原始误差 `e_raw`**。用滤波后的误差去算 τ 会形成「误差→τ→误差」的代数环：
   误差大→τ 小→误差看起来更大→τ 更小，反向则滞回，等价于自反馈，峰值会过冲且出现慢极限环。
3. **拐点必须落在 `eBand` 附近**。残余过冲 ≈ 饱和加速度 × τ(eBand)：若 `eBand` 处 τ 还是 30 ms，
   1700 目标下留下 `1146×0.03 ≈ 34 tick/s` 的过冲；`eLoFrac=0.30 / eHiFrac=0.90` 时降到 ≈9~14。
4. **`dV/dt` 掉速检测已删除**：实测恢复加速度 497~1146 tick/s² × 8.7 ms = 每次采样只差
   6~10 tick/s，**小于量化台阶 20**，逐帧差分全是噪声。掉速判据改用误差带（见 2.5）。

### 2.5 掉速态与积分冻结（取代 boost）

**状态机**（带滞回）：

```text
target == 0                        → 退出掉速
|e_raw| > dropEnterFrac·eBand      → 进入掉速（默认 3×eBand：1700→102, 2050→123, 2250→135）
|e_raw| < eBand                    → 退出掉速
target 改变                        → 退出掉速（并清 settleCnt、冻结计时）
```

**积分**：

```text
integralActive = target≠0 && !inDrop && |e_raw| < eBand
active  → integral += e_f·dt
target=0→ integral = 0
冻结    → integral 保持不动；冻结累计超过 iFreezeTimeoutSec 才清零
```

为什么**冻结**而不是清零、也不是继续累加：

| 方案 | 后果 |
|---|---|
| 继续累加（第 3 代 `iZone=500` ≫ 跌深 270） | 整个瞬态都在攒积分：`∫e≈52.5` → `iTerm=0.136` → 过冲 `≈iTerm/kp ≈ 75 tick/s`，与实测 +50~90 吻合 |
| 清零 | 恢复到稳态后积分要从 0 重新爬，稳态残差消失得慢；且清零瞬间输出有台阶 |
| **冻结（本代）** | 恢复期间不攒积分 → 过冲只由滤波残余造成（+10~20）；稳态原有积分原封不动，解冻立刻接着修残差 |

冻结是**状态保持**，解冻没有阶跃、不需要播种，这是它优于「清零/换积分器」的地方。
`iFreezeTimeoutSec` 是安全阀：万一误差长期卡在带外（堵转、目标不可达），不允许积分永久失效。

**为什么删 boost**：发射瞬间 `kS + kff·ω* + kp·e` 已经 > 1（2050 时 0.03+0.815+0.49=1.34），
占空比本来就顶到 1.0，boost 那 0.4 在饱和段贡献**恒为 0**（13/13 次发射实测恢复期 duty≥0.999）。
它唯一真实的作用是把退饱和点从 `e_desat=(1−ff)/kp`（1750→165、2050→102 tick/s）推到 `e≤0`，
即**抹掉整段线性收敛**，结构性造成 +50~90 tick/s 的过冲。

### 2.6 母线电压归一化（只乘前馈）与冻结

开启 `useVoltageNorm` 后：

```text
s = clamp(V_nom / V_busFilt, 0.85, 1.25)
ff = s · (kS·sgn(ω*) + kff·ω*)          // 只有这两项乘 s
P、I 不乘                                     // 环路增益不随电池状态漂移
```

机制与证据（2026-10-18 质疑答复）：归一化只影响「不同电量下同一目标要的占空比」，
不影响环路稳定性。09-05 19:16 那条日志（V_bus=11.55 V、目标 1700、稳态 duty=0.7553、`I=+0.0752`）：
若 `V_cal=12.0`，前馈应由 0.6807 升到 0.7072，积分应收敛到 **0.048**（而不是 0.075）。
所以归一化能吃掉电压失准那 0.027，**剩下的 0.048 是模型误差，必须多点重标 `kS/kff` 才能消掉**。

**为什么必须只乘前馈**：把 `s` 乘到整个输出上，等于把开环增益乘 `1/V_bus`——
低电压时环路增益被抬高 45%（`s=1.45` 时 `kp×台阶 → 0.053`），量化极限环重新出现；
而且 `s` 的滤波延迟（τ_bus）会跑进反馈通道，τ=0.3 s 时相角裕度从 102° 掉到 20°。

**为什么电压滤波必须冻结**：不冻结时，单发发射把母线拉低 3 V，τ_bus=1 s 的低通在
0.4~1 s 内把它当成「电池没电」→ `s→1.25` → 2050 处前馈 0.815→1.02，**输出 >1 又被饱和**，
等于人造了一次 boost。因此：`inDrop` 期间冻结、掉速结束后再 hold-off `busHoldOffSec=0.6 s`
躲开电池 RC 回弹，解冻后恢复 EMA。冻结超时 `busFreezeTimeoutSec=2 s` 用当前读数重播种。

### 2.7 到位判据 `isSettled()`

```text
eBand = max(settleFrac·|ω*|, 2·quantStep)     // 1700→34, 2050→41, 2250→45
|e_raw| ≤ eBand 连续 settleFrames(10) 帧（≈0.1 s）  → settled
```

这是 2026-10-16 报告「结论九」里唯一直接影响命中率、当时还没做的闭环项：
发射动作必须等 `isSettled()` 才允许开始。第 3 代那种 `|e| < 100 tick/s` 的松判据
（5 个台阶）不足以保证出球初速一致性，该字段已随重构删除。

### 2.10 整定流程（每个参数保留两种方法）

| 参数 | 方法一（首选） | 方法二（交叉验证） | 程序 |
|---|---|---|---|
| `kS`、`kff` | 多点稳态拟合 `d_ss = kS + kff·ω*`（≥2 点，斜率/截距） | 开环逐级功率扫描 | `Tune6.5 Feedforward`、`ShooterTuningTester` |
| `kp`、`ki` | 阶跃响应（`Tune6.1`：`Kd`、`τ` 反解模型式） | 临界比例度（`Tune6.3 Relay`：给 `Ku/Tu` 再按经验式折算） | `StepResponseTuner`、`RelayFeedbackTuner` |
| `tauVMax`、`tauVMin` | `Tune6.6 VelocityFilter`：稳态噪声 + 90% 滞后反解 | 阶跃响应的相位裕度复算 | `VelocityFilterTuner` |
| `tauBus` | `Tune6.7 BusVoltageFilter`：稳态纹波 + 单发跌落 | 换电池对比法（同一目标两种电量，前馈偏差 ≤0.5%） | `BusVoltageFilterTuner` |
| `eBand`、`settleFrames` | 由 `quantStep` 与 `settleFrac` 直接算，不整定 | — | — |
| `dropEnterFrac`、`iFreezeTimeoutSec` | 由 `eBand` 与实测跌深推出（3×/1.5 s） | — | — |

**必守顺序**：`kS/kff`（稳态）→ `kp/ki`（快速性）→ `tauV`（噪声与延迟的折中）→ `tauBus`（电量）。

### 2.11 离线复算

```java
FlywheelCalculator c = new FlywheelCalculator();
FlywheelParams.BIG.applyTo(c);
for (Sample s : csv) {
    c.calculate(s.target, s.velocity, s.vbus, s.dt);   // 与实机逐项一致
}
```

- 重载 `calculate(t, ω, V_bus, dt)` 是离线复算主入口；回放**无电压列**的旧日志请传
  `Double.NaN` 作电压（等价于 `useVoltageNorm=false`）。
  **不存在** `calculate(t, ω, dt)` 三参数无电压版本——Java 无法用「第三参数含义」区分重载，
  早期文档里写的该重载已删除（会编译冲突）。
- `calculate(t, ω, V_bus)` / `calculate(t, ω)` 自行用 `System.nanoTime()` 推 dt，只用于实机。
- `reset(ω)` 在从开环切回闭环前必须调用，否则滤波器从 0 爬升会造出假的巨大误差。

### 2.12 验收判据（改完必须逐条过）

1. `kp×step ≤ 0.05`（遥测不报 `HIGH`）。
2. 稳态：各工作点 `v_sd ≤ 0.6 个台阶`、`|误差| ≤ 0.12%·ω*`、`duty_sd ≤ 0.025`、饱和占比 0%（2250 除外）。
3. 积分：各档稳态 `|I integral|` 不得长期非零（目标 < `0.04/ki`）；多点重标后应 <0.02。
4. 发射恢复：跌幅 ~270~290 / 恢复中位 ≤0.43 s（不低于基线 5%）/ 过冲 ≤ +20 tick/s。
5. `isSettled()`：稳态后 0.1 s 内为 true；发射恢复期间为 false；不得抖动。
6. 电压：同一目标满电（12.9~13.1 V）与放电（~10.5 V）对比，`duty·V_bus` 差 ≤3%。

| 工具 | 位置 | 用途 |

| `FlywheelRun` | `OpModes/FlywheelRun.java` | 手动验证：START 后飞轮**静止**，`A→1600`、`B→1900`、十字键上下 ±100（按住连调）、`X→停`；Dashboard 勾 `logToCsv=true` 落 CSV，表头 `t,target,velocity,duty,voltage,error,vScale,inDrop,iActive,settled` |

1. **先 `FlywheelRun` 再动参数**：它的 CSV 足够覆盖 §2.12 的 ①②③⑤（稳态与到位判据），
