# 底盘 PIDSVA 自动标定操作指南

本指南说明如何使用 `AutomaticChassisCalibration`（Driver Station 名称 **`Cal: Chassis SVA/PID`**）
自动测定底盘的前馈参数（kS / kV / kA）与反馈增益（axial / lateral / heading 的 pos / vel 增益）、
以及运动约束（最大轮速 / 加减速度、最大角速度 / 角加速度）。

> **核心原则：本程序绝不写回 `MecanumDrive.PARAMS`。**
> 识别结果只在 Dashboard 显示建议值、并导出 CSV / SVG；由操作手核对后**手动**填回参数文件。

---

## 1. 标定对象与数学模型（为什么这样标）

标定对象是**底盘真实控制链路**（Road Runner 的 `HolonomicController` + `MotorFeedforward`），
**不是** `utility/PID/PIDSVAController`（后者为功率量纲，仅用于炮台 / 飞轮 / 吸球）。

```
前馈（电压→速度）：  u_volts = kS·sign(v) + kV·v + kA·a      power = u_volts / V_batt
反馈（位姿→速度指令）：v_cmd  = posGain·(位姿误差) + velGain·(速度误差) + v_desired
```

量纲约定（务必理解，填参数时才不会填错）：

| 字段 | 单位 | 说明 |
|---|---|---|
| `kS` | V | 静态补偿，克服静摩擦的电压 |
| `kV` | V/(tick/s) | 速度增益（`MotorFeedforward` 内部是 V/(in/s)，写入 PARAMS 时需 ×/÷ `inPerTick`） |
| `kA` | V/(tick/s²) | 加速度增益 |
| `axialGain` / `lateralGain` / `headingGain` | **1/s** | 位置增益（输出是速度，故量纲是 1/s，不是 1/s²） |
| `axialVelGain` / `lateralVelGain` / `headingVelGain` | **无量纲** | 速度增益 |
| `maxWheelVel` | in/s | 轮速上限 |
| `maxProfileAccel` / `minProfileAccel` | in/s² | 加速 / 减速上限 |
| `maxAngVel` / `maxAngAccel` | rad/s、rad/s² | 转向速度 / 角加速度上限 |

**量级自检基准**（标定结果应与现有 PARAMS 同量级，若差出 10 倍以上需怀疑接线 / 拟合出错）：

- `kS ≈ 1.2 V`，`kV ≈ 3.5e-4 V/(tick/s)`，`kA ≈ 7e-5 V/(tick/s²)`
- `axialGain 2 / axialVelGain 0.5`、`lateralGain 3 / lateralVelGain 1`、`headingGain 2 / headingVelGain 1`

## 2. 前置准备（开工前必须确认）

| 项目 | 要求 |
|---|---|
| 场地 | 机器人四周各留 **≥ 4 英尺（约 1.2 m）** 无障碍空间；地面干净、不铺毛毯以外的滑面 |
| 定位 | **必须**已接好并使用 `limelight` + Pinpoint 融合定位（`RobotPosition` 初始化依赖它）；标定用地面真值速度做打滑判据 |
| 电池 | 电量充足（≥ 12.5 V 静置）；标定全程电压会被记录，勿用低电量电池 |
| 起始姿态 | 机器人摆在场地某处、朝向任意；**同一轮标定中不要挪动**，机器人会自己走位 |
| 手机 / 电脑 | 能访问 FTC Dashboard（默认 `http://192.168.43.1:8080/dash`） |
| 硬件 | 四个驱动电机 + 编码器 + 电压传感器接线正常；`MecanumDrive.Params` 里 IMU 安装方向已填对 |

> **务必**在正式标定前先跑一次 TeleOp 确认定位、电机方向、前进方向都正确。
> 方向错会让 kS 出现负值或轮速恒为 0。

## 3. 部署与启动

1. Android Studio 编译安装：
   ```
   gradlew :TeamCode:assembleDebug
   ```
   或用 Android Studio 直接 Run。
2. 机器人端打开 Driver Station，选择 OpMode **`Cal: Chassis SVA/PID`**（在 **Calibration** 分组、Autonomous 类别下）。
3. **不要按 START**，先看 Init 界面确认：
   - 显示的「当前 PARAMS：kS / kV / kA」与「当前反馈 axial / lateral」符合预期；
   - 机器人已摆好、周围无人。
4. 把机器人放好、手离开 → 按 **START**。

## 4. 运行流程与手柄操作

按 START 后程序自动依次执行，**全程不要触碰机器人**，只在需要时按手柄：

| 手柄 | 时机 | 作用 |
|---|---|---|
| **START**（Driver Station） | Init 阶段 | 开始标定并自动进入首个阶段 |
| **B** | 任意阶段中 | **跳过**当前阶段（该阶段结果作废，后续阶段继续） |
| **Y** | 任意阶段中 / 结束后 | **立即急停终止**；结束后按 Y 退出建议值显示界面 |

阶段顺序与预计耗时：

```
预热 → SVA_RAMP → KA → FB_AXIAL → FB_LATERAL → FB_HEADING → ACCEL_SLIP → ANG → 建议值显示
```

| 阶段 | 机器人动作 | 时长（默认参数） | 产出 |
|---|---|---|---|
| 预热 warmUp | 小幅正向前进（0.25 功率，0.4 s） | 0.4 s | 稳定定位与轮速估计 |
| `SVA_RAMP` | 正向前进的三角波功率扫描（峰值 0.5，10 s 一来回） | ≈ 10 s | **kS、kV** |
| `KA` | 零均值正弦功率激励（0.5 Hz，幅值 0.5，6 s） | ≈ 6 s | **kA** |
| `FB_AXIAL` | 闭环前进阶跃（目标 +10 in） | 2.5 s | axial 增益 + ζ/ωₙ |
| `FB_LATERAL` | 闭环横移阶跃（目标 +10 in） | 2.5 s | lateral 增益 |
| `FB_HEADING` | 闭环转向阶跃（目标 +30°） | 2.5 s | heading 增益 |
| `ACCEL_SLIP` | 递增正负交替功率阶跃（0.3→0.9，4 级） | ≈ 4.6 s | 打滑前最大加速度 |
| `ANG` | 原地自转三角波扫描（峰值 0.6，8 s 一来回） | ≈ 8 s | 最大角速度 / 角加速度 |
| 建议值显示 | 停住、持续显示建议值 | 直到按 Y / 停 | 抄录 / 导出 |

**整轮默认约 36 秒。** 每个阶段都可以按 B 跳过（跳过的那部分不会出现在结果里）。

> 各阶段在移动中可能有 10~40 英寸的位移，务必保证场地空间。

## 5. 在 FTC Dashboard 上实时观察

打开 FTC Dashboard（`http://192.168.43.1:8080/dash`），进入 **Telemetry / Graph** 视图。
程序每帧只发**一个** packet，因此曲线不会互相覆盖。可用曲线键：

| 键 | 含义 |
|---|---|
| `measured` | 该阶段实测量（SVA/KA 为有效电压 V；反馈阶跃为位移或角度；ACCEL 为折算速度） |
| `model` | 模型预测值（SVA/KA 为按 kS·sign(v)+kV·v 预测的电压，用于看拟合偏差） |
| `residual` | 残差（实测 − 模型），**应接近 0 且无系统性趋势** |
| `extra` | 附加量（SVA/KA 为 0；反馈阶段为残留误差） |
| `wheelVelTicks` | 前进方向轮速（tick/s） |
| `wheelAccelTicks` | 前进方向轮加速度（tick/s²，EMA 平滑后） |
| `battVolts` | 实时电池电压（V） |
| `cal_done` | 结束后置 1，表示标定已完成 |

**判读要点：**
- `SVA_RAMP`：`measured` 应随功率升降呈三角波，`model` 应紧贴 `measured`；两条线分叉说明拟合失败或接线有问题。
- `KA`：正弦激励下 `residual` 应与加速度同相、幅值随频率变化，展开应近似直线。
- 反馈阶跃：观察 `measured` 是否平滑到达 `model`（目标线），**超调过大或长时间不到目标**说明当前增益不合适（这正是要标定的）。

## 6. 结果导出（CSV / SVG）

每次运行会自动在机器人存储建立新目录：

```
/sdcard/AutomaticCalibration/yyyyMMdd_HHmmss/
```

目录内容：

| 文件 | 内容 |
|---|---|
| `samples.csv` | 逐帧原始采样。列：`phase,t,battV,power,voltsEff,wheelVelTicks,wheelAccelTicks,poseVx,poseVy,poseOmega` |
| `results.csv` | 静态字段建议值。列：`field,unit,current,suggested,residual` |
| `fit_sva.svg` | 有效电压−轮速散点 + 前馈拟合直线 V = kS·sign(v) + kV·v |
| `residual_ka.svg` | 固定 kS/kV 后残差−加速度散点 + kA 拟合直线 |
| `fit_feedback_FB_AXIAL.svg` | 前进阶跃响应 + 目标线 + 峰值标记 |
| `fit_feedback_FB_LATERAL.svg` | 横移阶跃响应 |
| `fit_feedback_FB_HEADING.svg` | 转向阶跃响应 |

**取文件的方法：**
- 用 `adb pull /sdcard/AutomaticCalibration/ <本地目录>` 拉取，或
- 用手机文件管理器 / Robot Controller 的「文件传输」功能导出。

**SVG 是纯文本矢量图**，双击用浏览器打开即可，也可截图或转 PNG。

`results.csv` 的 `field` 行对应 PARAMS 里的字段名（如 `PARAMS.kS`、`PARAMS.axialGain`、
`PARAMS.maxWheelVel` …），`current` 是当前值，`suggested` 是建议值，`residual` 是拟合残差
（反馈增益行此处填的是实测阻尼比 `zeta`）。

## 7. 把建议值填回参数（手动）

打开 [MecanumDrive.java](../RoadRunner/MecanumDrive.java) 的 `Params` 静态类，逐项对照 `results.csv`：

```java
public static class Params {
    ...
    public double kS = <填 PARAMS.kS 的 suggested>;
    public double kV = <填 PARAMS.kV 的 suggested>;
    public double kA = <填 PARAMS.kA 的 suggested>;

    public double axialGain   = <填 PARAMS.axialGain 的 suggested>;
    public double axialVelGain = <填 PARAMS.axialVelGain 的 suggested>;
    public double lateralGain  = <填 PARAMS.lateralGain 的 suggested>;
    public double lateralVelGain = <填 PARAMS.lateralVelGain 的 suggested>;
    public double headingGain  = <填 PARAMS.headingGain 的 suggested>;
    public double headingVelGain = <填 PARAMS.headingVelGain 的 suggested>;

    public double maxWheelVel    = <填 suggested>;
    public double maxProfileAccel = <填 suggested>;
    public double minProfileAccel = <填 suggested>;   // 通常 = −maxProfileAccel
    public double maxAngVel      = <填 suggested>;
    public double maxAngAccel    = <填 suggested>;
}
```

> 也可在 FTC Dashboard 的 **Config** 标签页里临时改这些值做对比试验，但**编译前必须把定稿值写回源码**，
> 否则下次上电又变回旧值。

**填回后的验证：** 重跑一次本 OpMode，`current` 应接近上次的 `suggested`，且 `residual` / 超调变小；
再跑一次 TeleOp 和 Auto，确认路径跟踪无明显偏差或振荡。

## 8. 标定参数调优（可选的 `Cal` Config）

本 OpMode 的参数类 `Cal` 可用 Dashboard 的 **Config** 页实时调整并保存。常用：

| 参数 | 默认 | 调整建议 |
|---|---|---|
| `SVA_RAMP_MAX_POWER` | 0.5 | 场地小可降到 0.4；要覆盖更高速可提到 0.6~0.7 |
| `SVA_RAMP_TIME` | 5.0 | 慢速底盘或电机响应慢时加大到 6~8 s |
| `KA_AMPLITUDE` / `KA_FREQ_HZ` | 0.5 / 0.5 | 频率过高噪声大，过低加速度不足；一般保持 |
| `FB_STEP_DIST_IN` | 10.0 | 场地紧可减到 6；测阻尼建议 ≥ 8 |
| `FB_STEP_HEADING_DEG` | 30.0 | 按可用转向空间调整 |
| `ZETA_TARGET` | 0.9 | 期望阻尼比；想更跟手可到 0.95，想更快可到 0.7 |
| `OMEGA_TARGET_SCALE` | 1.0 | =1 保持实测带宽；>1 提速（注意别过头引起振荡） |
| `SCALE_MIN` / `SCALE_MAX` | 0.5 / 3.0 | 单次修正幅度上下限，防噪声把增益顶飞 |
| `SAFETY` | 0.85 | 运动约束安全系数，取标定峰值的 85% |
| `SLIP_TOL` | 0.25 | 打滑判据相对容差 |
| `VEL_EPS_TICKS` | 20.0 | SVA 拟合死区，剔除静止点 |
| `EMA_ALPHA` | 0.35 | 轮速 / 加速度平滑；噪声大时减小（如 0.2） |

## 9. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 建议 kS 为负 / 异常 | 前进方向判断错、右轮接线或方向反了 | 跑一次 TeleOp 确认四轮正向前进；检查 `MecanumDrive` 电机 REVERSE 设置 |
| 建议 kV 大 10 倍以上 | 编码器换算 `inPerTick` 错，或轮速单位错 | 核对 `PARAMS.inPerTick`；确认标定时电机确实是 tick 读数 |
| `SVA_RAMP` 时 `model` 与 `measured` 明显分叉 | 拟合失败 / 电机供电不足 / 电池掉压 | 看 `battVolts` 曲线；换满电电池；降低 `SVA_RAMP_MAX_POWER` |
| `KA` 拟合失败（残差无斜率） | 加速度激励不足或脉冲太短 | 提高 `KA_AMPLITUDE` 或延长 `KA_TIME`；确认 `EMA_ALPHA` 不过大 |
| 反馈阶跃需要 B 跳过 | 增益太差导致振荡 / 走飞 | 先用当前值跑；结果仍可用，只是阻尼比估计偏差大 |
| `ACCEL_SLIP` 全程报警打滑 | 前进方向错 / 地面太滑 | 检查方向；换场地；提高 `SLIP_TOL` |
| 结果 `suggested` 全是 NaN | 对应阶段被跳过 | 重跑，别跳过；或用 `current` 值兜底（程序已对约束做兜底） |
| 找不到 CSV / SVG 文件 | 存储权限未授予 | 在手机设置里给 Robot Controller 存储权限后重跑 |
| 机器人中途停 | 定位 / 硬件报错或按了 Y | 看 Driver Station 与 `RobotLog`（TAG `Cal`）日志 |

## 10. 重要限制与注意事项

1. **不写回参数**：一切结果都需手动填回，程序不会替你做决定。
2. **单次结果有噪声**：建议**连续标定 2~3 次**，取稳定一致的结果（或对 `results.csv` 取平均）再填回。
3. **跳过的阶段没有结果**：对应 `suggested` 列为 NaN，请勿直接填入。
4. **运动约束是「打滑前的峰值 × 安全系数」**，是保守值；追求极限可在验证后手动上调。
5. **打滑判据依赖定位地面真值**：若 LiDAR / Limelight 未启动或定位漂移，打滑判据会误报。
6. **占位提醒**：Init 界面里出现的 `A` 字样为历史遗留提示，实际**只用 START 启动**；阶段中只用到 B / Y。
7. 标定结束时，界面会一直显示建议值，方便抄录；按 **Y** 退出（或按 Driver Station 的 STOP）。
```
